## 它做什么（大白话）

- **两个真窗口并排**。横屏左右，竖屏上下，中间一条 6 px 的深色缝（#242424），四角圆角 10。窗口还是应用自己的窗口，只是被摆成了两半，所以应用自己的拖放照常能用：Dolphin 的文件能拖进 Telegram。
- **进分屏**，三条路进去以后都一样：活动应用去左半（竖屏上半），另一半出「选择另一个应用」。
  - ① **拖标题栏到左边或右边**（竖屏上边或下边）。窗口缩成一张卡跟着手指走，离边 36 以内，目标那半屏出深色提示框「松手进入分屏」，松手进分屏。
  - ② **控制中心拇指栏第 6 行的「分屏」磁贴**（四格里最右那格）。
  - ③ **多任务卡片名字后面的 ▾ →「分屏」**。打开那张卡后进分屏。
- **「选择另一个应用」**：另一半是模糊壁纸压 36 % 黑。上面一排「已打开」的窗口缩略图，下面一排「其他应用」（Dock 上还没开的）。点一个，它就去这半边；点空白处取消，前一个应用回原样。从别处（Dock、多任务卡片）激活一个应用，也算选了它。
- **分隔线**：中间一根白色小横条。
  - 按住拖：两边各盖一层应用底色加图标（遮罩），松手吸附到 30 / 50 / 70 % 里最近的那个，窗口才一次改到新大小。
  - 拖到离边不到 15 % 松手：被挤的那个退到后台（最小化，还开着），另一个全屏。
  - 点一下出菜单「对调应用 / 退出分屏」。
- **拖标题栏**（已经在分屏里）：拖到另一半 =「松手对调」；横屏下拖到顶上 =「松手进入全屏」（退出分屏，它全屏）；松在中间就飞回原位。还在选应用时拖到顶上 = 取消。
- **回桌面**（底边上滑、桌面键）两个一起收；之后从 Dock、多任务卡片或别处点开其中任何一个，另一个一起回来，还是并排。
- **关掉一个**：另一个全屏。点它的最大化按钮或双击标题栏：退出分屏，它全屏。
- **台前调度开着时它不管事**：磁贴变暗，点了只提示「台前调度开着，把卡片拖到舞台上就能并排」；▾ 不出现；拖标题栏也不进分屏。分屏开着的时候打开台前调度，两个窗口原样交给台前调度。
- 游戏、串流这类受保护的窗口不进分屏（名单和台前调度、多任务卡片是同一份）。应用的最小宽度放不进半屏时，提示「这个应用不支持分屏」。

## 实现要点

**为什么是真窗口、不是画出来的**：分屏的意义就是两个应用能互相拖东西。KWin 内部窗口收不到应用的拖放（台前调度踩坑第 28 条），所以两半必须是应用自己的窗口，在 KWin 自己的几何里摆好。脚本只摆位置、调大小，不碰应用的内容。

**脚本自己的窗口**（`Split.qml` 里六个 `Window`，都是 KWin 内部窗口，标题以 `y700-split ` 开头，不进任务切换器）：
- `bar`：拖分隔线时整条缝的触摸区。
- `handle`：小横条的触摸区 48×90，横条 4×40，按住亮一块 20×90 的胶囊。
- `overlay`：飞行层、遮罩、拖标题栏的卡片、提示框。
- `picker`：选择面板。
- `menu`：「对调应用 / 退出分屏」。
- `toast`：一行提示。

不用的时候停在 x = −32000，不销毁。KWin 按显示的先后叠内部窗口，所以加载时按 bar → handle → overlay → picker → menu → toast 的顺序一次性显示。

**缝和圆角为什么由特效画**：要是脚本自己开一个全屏窗口垫底色，它会盖在 Dock、通知横幅和跨过缝的菜单上面。所以底色交给圆角特效，画在两个分屏窗口里叠在下面的那个的位置（见下）。

**进分屏**：
- 拖标题栏走 `interactiveMoveResizeStarted/Finished`。快捷键 `y700-split` 调 `tile()`：活动应用去左半，右半出面板。
- 快捷键按下时还没有活动应用的话（帘子、卡片正在退场，应用马上就上来）：等 1 s，这期间第一个激活的应用算数，否则提示「先打开一个应用」。
- 已经在分屏里：提示「已经在分屏里了」。

**选择面板**：
- 「已打开」取 `stackingOrder` 里能摆的窗口，上面的排前面。「其他应用」是 shellbar `dockApps()` 去掉已经开着的（按 desktopFileName、wmclass 比）。底图是 `wallpaperUrl()`。
- 点图标调 `launchApp(id)`。之后新来的窗口（`windowAdded`）或者别处激活的窗口（`windowActivated`）都当成选中。
- 键盘、控制中心、应用网格在前面时面板先等着（`blocked`）。
- shellbar 不在或是旧版（没有这三个方法）时，调用静默失败：没有底图（纯色），只有「已打开」。

**飞行**（`fly()`）：
- 进分屏、对调、吸附、出分屏都是缩略图（`WindowThumbnail` 副本）在 overlay 里飞，真窗口藏在下面（透明度 0）。
- 副本一接手就把真窗口摆到新位置，等它按新大小画好（最多 400 ms）再显示真窗口、撤副本。
- 副本先定格再藏真窗口，原因见踩坑 1。

**分隔线**：
- 按下时两个副本正好盖在两个窗口上。
- 一拖动，真窗口就藏到副本下面（`divMoved`），副本跟着手指变大小，各盖一层应用底色加 50 的图标（遮罩）。
- 松手：吸附点和拖到头的判断照设计稿；拖到头时被挤的那边越来越暗，最多压 60 %。
- 没拖动就是一次点击，出菜单。

**比例**：按扣掉缝之后的长度算（横屏 1600 − 6 = 1594），见踩坑 3。

**拖标题栏**：
- 判断「在哪个区」要手指位置。KWin 只告诉脚本窗口的几何，`Workspace.cursorPos` 是指针的，触摸不动它（踩坑 2）。
- 所以拖动期间每 8 ms 问一次特效的 `touchPoint()`。拖动一结束就停，平时不轮询。
- 没有特效时退回 `cursorPos`（鼠标拖照样能用）。
- 卡片的缩放用弹簧（k 900，ζ 1.5），背后压暗 40 %。

**一起收、一起回来**：
- 底边上滑和桌面键只最小化**活动**窗口。脚本看到用着的那个被最小化，就把另一个也最小化（日志 `parked`）。
- KWin 先把焦点交出去、再告诉脚本窗口最小化了，所以「50 ms 内刚失去焦点的」也算活动的。
- 不在用的那个先被最小化的话，等 300 ms：两个都下去了 = 回桌面，只下去一个（多任务卡片「只回来选中的应用」）= 把它拉回来（`settle()`）。
- 任何一个被重新显示或激活，另一个跟着上来，叠在它正下面（`bringPartner()`）。KWin 脚本 API 有 `Workspace.raiseWindow` 就用它；没有时交替设两次 `activeWindow`（加载那行日志写成 `loaded (no raiseWindow)`）。`split.sh` 的 `api` 一步会打印这个 KWin 有没有 `raiseWindow`、`stackingOrderChanged`；脚本不靠 `stackingOrderChanged`。

**最大化**：
- 应用被摆进半屏后，2 s 内自己又最大化了（它在恢复上次的状态），算它的，再摆一次，每个窗口只摆一次（`refit`）。
- 之后的最大化是人做的（双击标题栏、按钮）：退出分屏，它全屏。
- 脚本自己调 `setMaximize` 的回声要过一会儿才从客户端回来，所以只认「最大化了」这一种。

**跟台前调度让开**：
- 看卡片列内部窗口的标题（`Stage.qml` 开着时带 ` on`）。
- 打开台前调度时，正在进行的拖动、遮罩、菜单都收掉，两个窗口原样留下（`dropPair(true)`），交给台前调度去摆。

**转屏、键盘**：工作区一变，300 ms 后统一重摆一次（转屏和停靠键盘的工作区要晚一点才稳）。

**卸载**（`install.sh` 换新构建、`--remove`）：断开所有信号，藏着的窗口恢复透明度，分屏里的窗口还原，特效的两张单清空。

**`Debug=true`**（只在测试床开）：每次状态变化一行 `y700-split: state …`，带窗口标题。标题可能有私人内容，所以真会话里不开。

**圆角特效**（`linux/stage/kwin-corners`，和台前调度同一个特效 `y700_stagecorners`，接口全文在 `stagecorners.h` 头上）：
- `setSplitWindows(ids)`：分屏的两个窗口，圆角 10。同时在台前调度单子上的窗口用台前调度的 20。
- `setSplitChrome("x y w h")`：工作区。特效在两个分屏窗口里叠在下面那个的位置画 #242424，它下面的窗口在这块里不画，于是缝和圆角露出底色，叠在两个窗口上面的东西（Dock、横幅、菜单、别的窗口）照常盖在上面。
  - 开着时分屏窗口不画阴影（vivo 的没有；Breeze 的会落到另一半上）。
  - 最下面那个按「有变换」画，原因见踩坑 6。
  - 只有这时 `isActive()` 为真、进绘制链；关着时特效不在绘制链里。
- `touchPoint()`：手指按着时回 `"x y"`，没按着时回空串。
- 脚本加载时调一次 `loadEffect("y700_stagecorners")`。特效没有或者是旧版（没有分屏这部分）时，调用静默失败，脚本照样跑：方角、缝里是下面的窗口、卡片跟着光标。

## 安装

每一步都要作者当轮点头。装和重启分开；重启控制中心、shellbar、KWin 脚本前先跟作者说一声，确认平板没在用。装之前先拿平板上的镜像和 git 逐个比 sha256。

1. **圆角特效的分屏部分**：把 `linux/stage/` 更新到 `/usr/local/src/y700-stage/`，root 跑 `sh install.sh`。它重编特效、重装台前调度脚本（开关状态不变）。**特效新代码要下次登录才生效**（已加载的特效一直跑旧代码）。
2. **分屏脚本**：把 `linux/split/` 放进 `/usr/local/src/y700-split/`，root 跑 `sh install.sh`，看到 `INSTALL_OK build <id>`。
   - 它会：先卸载旧的；拷进新的 `build-<id>` 目录；写 kwinrc `[Plugins] y700-splitEnabled=true`、`[Script-y700-split] BuildId=<id>`、`[Windows] ElectricBorderTiling=false`、`ElectricBorderMaximize=false`；`reconfigure`；等最多 3 s 看 `isScriptLoaded`。
   - 第一次装加载不上的话，按路径 `loadDeclarativeScript` 兜底，原因见踩坑 4。
   - 最后查这次以来的日志里有没有本构建的 QML 报错，有就 `INSTALL_FAIL`。
   - 脚本当场生效，不用重登。
3. **多任务卡片 ▾**：照 `linux/gesture/taskswitcher/install.sh` 头上的说明装。补丁或界面文件变了，下次登录才生效（KWin 按 URL 缓存特效的 QML）。
4. **控制中心磁贴**：控制中心镜像 `/usr/local/src/y700-control-center/` 更新后 `sh install.sh`，它会重启控制中心服务。
5. **shellbar 三个方法**：shellbar 镜像 `/usr/local/src/y700-shellbar/` 更新后 `sh install.sh --no-start`，再单独重启 `y700-shellbar.service`，方法和开发日志（未公开）「Dock 与状态栏」11-09 那次一样。
6. **重新登录一次**：新特效（圆角、缝的颜色、手指位置）和新多任务卡片才上。
7. 跑体检，看「分屏」「台前调度」两行。

**顺序不要紧，缺哪块都能跑**：
- 没有新特效：方角、卡片跟光标。
- 没有新 shellbar：面板只有「已打开」，没有底图。
- 没有 ▾、磁贴：只能拖标题栏进。

## 踩坑（根因）

1. **KWin 的窗口缩略图跟着窗口透明度走**：真窗口藏起来（透明度 0）以后，实时副本也是空的，飞行时一片透明。所以副本先定格（`freeze()`，留住最后一帧），再藏真窗口。拖标题栏的卡片也一样：先画出一帧（50 ms），再藏窗口。
2. **`Workspace.cursorPos` 是指针的位置，触摸不动它**（ts-bed 11-10）。拖标题栏时 KWin 只给窗口几何，于是在特效里加了 `touchPoint()`，读 KWin 触摸输入最后一个事件的位置。
3. **比例按扣掉缝的长度算**。70 % 是 `round(0.7 × 1594) = 1116`，缝 6，剩下的 478 给另一个。不是用整屏宽再扣一次缝的 472。剧本和设计稿里的数字都按这个。
4. **KWin 起来以后才拷进去的脚本包，写 `Enabled` 再 `reconfigure` 不会加载**（sb-bed 11-10）。台前调度能这样加载，是因为它的包在 KWin 启动时就在作者的数据目录里。`loadDeclarativeScript(路径, "y700-split")` 能加载，用这个名字，配置组还是 `[Script-y700-split]`。`install.sh` 第一次装时用它兜底，下次登录起按插件正常加载。
5. **KWin 按 URL 缓存脚本的 QML，进程活多久缓存多久**：原地覆盖文件，跑的还是旧代码。所以每次装一个新的 `build-<id>` 目录（新 URL），先 `unloadScript` 再加载。和台前调度一样。
6. **分屏窗口里最下面那个要按「有变换」画**：KWin 6.6 的 `WorkspaceScene::paintSimpleScreen` 会把没变换的窗口的绘制区裁到它自己的范围，缝和圆角外的底色就画不出来。代价是它下面的窗口失去遮挡剔除，由「这块里下面的窗口不画」补回来。
7. **sb-bed 的 `tap()` 有一根按住的手指，会抢走点给 KWin 内部窗口的那一下**：KWin 的触摸焦点由第一根手指定，后面的手指都给同一个表面。应用在按住的位置上时（进分屏后 Kate 占了左半），第二根手指也去了 Kate。点内部窗口（面板、菜单）用单指，它们本来也不需要按住的那根。
8. **菜单按下高亮要圆角 12**：方的会从外框圆角 18 上戳出 4.6 px。
9. **应用摆进半屏后自己又最大化**（恢复上次的状态）：2 s 内的那次算它的，再摆一次（`refit`），不当成用户要全屏。
10. **回桌面只最小化活动窗口，而且 KWin 先交出焦点、后报最小化**：用 `prevActive` 加 50 ms 窗口认出「刚才用着的那个」，见「实现要点 · 一起收、一起回来」。

设计稿自查时的坑：
- 无头 Edge 截图：手指还按着的状态（`#shot-drag`、`#shot-title`）动画循环一直在跑，CSS `transition` 走不完，截出来是过渡的半路。设计稿里状态栏的背景过渡因此去掉了；看截图时别把这类半透明当成毛病，先看 DOM。
- Git Bash 里直接跑 msedge 再接管道，11-10 拿不到 `--dump-dom` 的输出；改用 PowerShell 的 `Start-Process -RedirectStandardOutput`。
- 缩略图是 `<button>`，里面的假标题栏按钮不能也写成 `<button>`：嵌套按钮会被解析器拆开，缩略图铺满半屏。已改成 `<i class="tb">`，自检里有一项 `thumbnails intact` 盯着。

## 有意不做

- **「保存组合」**：作者 11-10 定先不做。要改 Dock，以后想要再加。
- **小窗**（自由浮动窗口）：作者定只做分屏。拖标题栏松在中间就飞回原样，不留成浮窗。多任务卡片的 ▾ 里因此只有「分屏」一项。
- **拖分隔线时窗口实时变大小**：作者选了遮罩，vivo 和安卓也是这样。Chrome、Telegram 改大小慢，实时会露黑边、画面拉伸。
- **横屏下切上下分屏**：1600×1002 上下分，每个只剩不到 490 高。转到竖屏会自己变成上下分。
- **三指上滑进分屏**：三指上滑在我们这儿已经是 KWin 的概览。
- **拖 Dock 图标进分屏**：普通桌面下应用一打开，Dock 就收起来了，拖不着。
- **分屏窗口顶上的焦点小横条**：我们的应用都有标题栏，前台那个的标题栏本来就亮。
- **回桌面时两个一起缩到 0.9 淡出**（设计稿里的样子）：没做，两个窗口各走 KWin 自己的最小化动画。要做得在飞行层里另画一段，收益小。
- **KWin 自带的拖到边半屏、拖到顶最大化**：装上后关掉（`ElectricBorderTiling`、`ElectricBorderMaximize`），因为它们抢同一个拖动。没最大化的窗口拖到顶也不再最大化；在分屏里拖到顶是「进入全屏」。`--remove` 会还原。
- **台前调度开着时 ▾ 消失**：ts-bed 没测。测试床里两个脚本一起加载时，卡片列标题要等台前调度真的开起来才变，剧本不好等。
- **`Debug` 日志在真会话里不开**：带窗口标题。
