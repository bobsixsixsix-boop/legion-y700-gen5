# Y700 台前调度设计稿（2026-11-08）

## 1. 台前调度是什么

**大白话**：台前调度是苹果 2022 年给 iPad 和 Mac 加的一种窗口管理方式。屏幕中间叫「舞台」，只放你正在用的那一组窗口。左边一竖条放最近用过的几组，每组是一张小缩略图。点一张，当前这组缩回条里，点中的那组回到舞台，窗口还在原来的位置。把一张缩略图拖上舞台，两组就并成一组，以后一起进出。它相当于把多任务切换常驻在屏幕边上。

**精确要点（以 iPad 为主）**
- 默认关，靠控制中心的按钮开关。长按这个按钮，可以单独关掉「最近应用条」或 Dock。
- 一块屏同一时间只有一组在舞台上。开新应用就新建一组，旧组缩进左条。
- 左条在 iPadOS 16 最多放 4 组。每张是整组的实时缩略图，画成斜着的 3D 卡，下面一排是应用图标。同一应用的几个单窗组会叠成一摞。
- 窗口数：16 版一组最多 4 个窗口，第 5 个会把最旧的挤出去。17 起可以自由摆放、互相重叠。26 把上限和摆放规则都去掉了。
- 怎么并组：把缩略图拖上舞台；从 Dock 长按拖上来；用窗口菜单的「添加窗口」；或者 Shift+点。
- 怎么拆组：最小化或关闭窗口。26 里最小化的窗口会自己成一组。关掉组里最后一个窗口就回主屏。
- 把窗口拖到条的上方，条会让开。
- 切换动画是窗口缩进条里，选中那组再放大回原位。苹果没公布时长。评测估计 0.35–0.5 秒、带弹簧、中途可打断，这一点未核实。
- 大家主要骂这些，我们照着避开：
  - 16 版尺寸只有几档可选、会自动重排、有 4 窗上限；
  - 条上的卡片没有名字、没有关闭按钮、没有菜单；
  - 条和 Dock 占地方；
  - 转屏后布局丢失；
  - 26 版窗口会莫名消失，退出这个模式后组也没了。

## 3. KWin/Plasma 自带的能顶多少

| 功能 | 能顶哪部分 | 差在哪 |
|---|---|---|
| 概览（Meta+W）、窗口视图（Meta+F9 等） | 能铺开看窗口 | 模态，用完就收，没有组。窗口视图有 D-Bus 方法 `org.kde.KWin.Effect.WindowView1.activate(as)`，能只铺开指定的几个窗口，第二版做「展开一组」可以直接调 |
| Thumbnail Aside（Meta+Ctrl+T） | 能把缩略图钉在右边 | 点了没反应；要手动一个个加；不按最近使用排序 |
| Alt+Tab 主题 | 能切窗口 | 要按住修饰键，触屏没法用 |
| 活动、虚拟桌面 | 最像「组」 | 平板只开了一个虚拟桌面（[R]:2920）；切换时没有侧边缩略图；顺序固定 |
| 平铺编辑器（Meta+T） | 能把一组窗口排好 | 不管谁在舞台、谁在条上 |
| 显示桌面 | 能一下全收 | 只隐藏不最小化，仓里早定了不用（[R]:2895–2897） |
| 多任务卡片 | 能切应用 | 模态；选中一个会把其他窗口全最小化 |

结论：没有一样能做到「常驻侧边条 + 组」。bugs.kde.org 搜「stage manager」0 条结果。KDE Discuss 上 Nate Graham 2026-07-26 回帖，不看好常驻缩略图这个点子。官方短期不会做，只能自己写。

## 4. 推荐方案

**在哪实现**：新写一个声明式 KWin 脚本 `y700-stage`（QML + JS，跑在 KWin 进程里）。一个组件同时管组的状态、摆窗口和画侧边条。

**为什么不是测绘里建议的 A+C**（JS 脚本管窗口，shellbar 画条）：
- HyprKwin 在 6.6 上已经证明了三件事：声明式脚本能开 QML Window，里面能放 `KWin.WindowThumbnail`，也能写 `frameGeometry` 摆窗口。测绘里标「未核实」的两件事因此有了上游实证，但平板上仍要先验。
- shellbar 做不了这件事的关键两块：拿不到缩略图（screencast 授权没核实，PipeWire 一张一路录屏也费电），也不能摆窗口。拆成两个进程还得互相对状态。
- 它跑在 KWin 里，不是新的常驻进程，不触发「常驻用 Rust」那条规矩。
- 改脚本不用重登（unloadScript 加 reconfigure）。有一个推断：KWin 对特效按 URL 缓存 QML，HyprKwin 的 main.qml 是一个按 BuildId 加载正文的 Loader，看起来就是为了绕开这个缓存。我们用同样的思路，代码自己写。

**备胎**：如果第一天验出 KWin 内部窗口收不到触摸，条带就改放进 y700-shellbar（layer-shell，触摸已经验证过）。脚本只管窗口，两边走 D-Bus。

**不选的两条路**：
- 扩展多任务卡片：特效只在打开时存在，做不了常驻条；QML 改了要重登；编坏了 KWin 有崩溃循环的风险。
- KWin C++ 插件：每次升级 KWin 都要重编，仓里已经否过几次。

**复用什么**
- HyprKwin（GPL-3.0-or-later）。下面是调研时打算参考的地方。最后只借了思路，代码都是自己写的，没有拷它的，所以 `y700-stage` 不带它的许可（见 [README.md](README.md)「实现要点」）：
  - StagePreview 的 Window flags；
  - StageCard 的缩略图卡；
  - placeStage 里条宽和舞台区的算法；
  - 「先把窗口挪回舞台，50 ms 后再激活」；
  - BuildId Loader；
  - 常驻覆盖窗平时停在 -32000，避开开窗动画。
  - 不要：倾斜矩阵、阴影、平铺布局。
- y700-taskswitcher：StackCard.qml 的缩略图圆角和 textureSize 算法，stack.js 的弹簧，受保护窗口名单（[SJ]:130–133）。
- y700-home 和 y700-edge：安装流程、注册快捷键、callDBus、体检写法。
- 别家的点子：expect 集合、记账（Ledger）、1 秒防重入。

**分工**

| 谁 | 现在管什么 | 台前调度开着时怎么配合 |
|---|---|---|
| 底边（y700-taskswitcher） | 回桌面、多任务卡片、沿底边横划 | **特效不改**。回桌面 = 整组下台（见下面的连发规则）。在卡片里选中一个应用 = 切到它那组：脚本看到激活后，把组员恢复，把别的组收起 |
| 左右边（y700-edge） | 返回 | 卡片从 x=20 开始，不压 8 px 的边缘条。从边上起手的划动仍然是返回 |
| 顶边（shellbar） | 状态栏、通知、控制中心 | 不变。舞台从状态栏下面算起，用 `clientArea(MaximizeArea)` |
| Dock（shellbar） | 启动应用、`requestActivate` | **不用改**。开新应用 = 新组上台；点一个已经在条里的应用 = 切到它那组 |
| 控制中心 | 磁贴 | 加一块「台前调度」磁贴，调 `invokeShortcut y700-stage-toggle`，和「多任务」磁贴同一种写法 |

**窗口怎么藏**：默认用真最小化。理由有三：
- 仓里的规矩是收起窗口要用真最小化，这样 shellbar 也看得见；
- 最小化的应用一般不再出帧，空闲时最省电；
- 不会有窗口留在屏幕外，不用做崩溃恢复。

挪到屏幕外的做法也写成可换的策略，只作实验开关。

最大的未知：最小化窗口的 WindowThumbnail 有没有画面。退路按顺序是：
1. KWin 留着最后一帧就直接用；
2. 最小化前对缩略图调 `grabToImage`，存一张静态图（可不可行未核实）；
3. 卡片改成图标加名字。

## 5. 第一版范围（MVP）

**功能**
1. 开着时，一组在舞台。左条最多放最近的 4 组，最新的在最上面。
2. 新窗口 = 新组上台，旧组下台。对话框和 transient 窗口跟着主窗口走，不算新组。
3. 点卡 = 换组。
4. 拖卡上舞台 = 并组。一组最多 2 个窗口，左右各占一半。按松手位置决定放左半还是右半。手指移动超过 16 px 才算开始拖。
5. 长按卡 500 ms 弹出菜单：「拆开」（只有两窗组才有）和「关闭」。
6. 点舞台上某个窗口标题栏的最小化 = 这个窗口单独成组下台，剩下那个铺满舞台。
7. 组里最后一个窗口关掉 = 舞台空出来，露出桌面，条还在。
8. 从别处激活了某组的窗口，比如 Dock、多任务卡片、通知、应用自己抢焦点，就切到那组。切完 1 秒内，旧组再抢焦点不理。

**连发规则**：一组的窗口在 300 ms 内全部被最小化（回桌面手势、显示桌面），算整组下台，不拆。只最小化一个、另一个还在，就把它拆出去。这个计时器只在最小化事件到来时才起，平时不唤醒。

**布局**（横屏逻辑 1600×1002，缩放 1.9）
- 所有位置和尺寸都取 10 的倍数，乘 1.9 后正好落在整设备像素上。
- 条宽 160（设备 304 px）：左边留 20 躲开返回边，卡宽 120，右边留 20。
- 卡片：
  - 缩略图区 120×80，接近舞台的比例；
  - 下面一行 30 高：单窗组放 20 的图标加 14 px 的应用名，两窗组放两个图标；
  - 卡与卡间距 20。4 张总高 500，竖着居中，大约在 y 265–765，左手拇指够得着。
- 舞台区：x 从 160 到 1600，宽 1440，从状态栏下面到底。工作区的精确高度没量过，预计 974。单窗铺满舞台，两窗各宽 720，中间不留缝。
- 样式：
  - 条的底色和状态栏一样用 #0e0f12，不透明、不模糊。这样省掉模糊闪烁那一整套坑，白字在亮壁纸上也看得清。
  - 卡片平放不倾斜，圆角 10，没有阴影。描边宽 1 个设备像素（逻辑 1/1.9），白色 8%。
  - 按下缩到 0.97，160 ms。
- 用户把舞台上的窗口最大化或全屏时，条带淡出；退回来再淡入。

**动画**（都在 300 ms 以内）
- 换组：240 ms，曲线 [0.32,0.72,0,1]，和 dock 用的是同一条。旧组缩到它的卡位，新组从卡位放大到舞台。中途再点会接着改目标。
  - 思路参考 HyprKwin：在覆盖窗里飞缩略图，真窗口在下面一步到位。
  - 先要验 KWin 自带的最小化特效会不会叠上来。平板上开的是哪个最小化特效没核实。如果叠上来又压不住，第一版降级成卡片 160 ms 淡入淡出，飞的效果放到第二版。
- 卡片重排 200 ms；新卡从上方滑入 200 ms；条带淡入淡出 160 ms，曲线 ease-out。
- 减弱动画时（Kirigami longDuration < 1）全部瞬时完成，照 [TS]:42 的写法。

**开关**
- 控制中心磁贴。开关状态要跨重登保存，具体存在哪里（打算用 kwinrc 的脚本配置加 readConfig）写的时候再核。
- 关掉时：舞台上的窗口还原到进舞台前的大小和最大化状态（脚本会记一本几何账）；条带消失；其他组照旧最小化着，从多任务卡片里找。

**特殊窗口**
- 不纳管的窗口：dock、skipTaskbar、对话框和 transient、modal、不能缩放或固定尺寸的（和 HyprKwin 的 shouldTile 同一套判断）、屏幕键盘、控制中心、shellbar、通知。
- 受保护窗口（游戏、LIVI、moonlight）：不缩、不藏、不进组、不上条。它在前台时条带藏起来。
- 全屏应用：不动它，条带藏起来。
- 屏幕键盘弹出时：不重排舞台，免得窗口跳。

**竖屏**（1002×1600）：第一版先暂停。条带藏起来，舞台窗口回到整屏，组的账照样记着，转回横屏就恢复。几何账横屏、竖屏各记一份。

## 6. 有意不做（第一版）

- **3D 倾斜卡片、阴影、背景模糊**：作者要扁平，模糊还有闪烁的坑。
- **从 Dock 长按拖应用上舞台**：Dock 在另一个进程，跨进程拖放没有现成的路。
- **一组 3–4 个窗口、自由叠放**：1440 宽分三份每份才 480，太窄。
- **同一应用叠成一摞、条带滚动**：4 组以外的从多任务卡片里找。
- **拉出条带的边缘手势**：四条边都已经有主了。
- **在多任务卡片里按组显示**：要动特效、要重登。多任务卡片 10-21 也有意没做小窗和分屏菜单（[R]:3159，那段没写原因），所以分组只在侧边条做。
- **外接显示器各自一个舞台**：外屏没有触摸，多任务卡片也不管外屏（[R]:3491）。
- **组跨重登保存**：重开以后窗口对不上号。
- **甩窗半屏、四角停放**：和现有的边缘手势、平铺冲突。

## 7. 风险与要作者定的

**风险**
- KWin 内部窗口收不到触摸。对策：换 shellbar 那个备胎。
- 最小化窗口的缩略图是空白。对策：按第 4 节的退路一级级降。
- 多任务卡片的 finishOpen 和脚本恢复组员会抢先后。对策：在 ts-bed 的 races 场景里压测。
- 点侧边条不是从边缘起手，拿不到 GPU 加速。GPU 停在 160 MHz 时 p95 是 14.5 ms，超过 120 Hz 的帧预算。对策：先测帧；不够的话让加速规则也认左边 160 px。加速那段代码我没读，好不好加未核实。
- 快捷键 `y700-home-minimize` 只最小化当前窗口，台前调度开着时会把两窗组拆开。
- 和 Meta+T 平铺可能抢窗口，HyprKwin 就有这个问题。作者用不用 Meta+T 我没核实。

**要作者定的**
1. 怎么藏窗：最小化，还是挪到屏幕外？**推荐最小化**，空闲最省电。先测缩略图有没有画面再定。
2. 侧边条：常驻并让位（舞台宽 1440），还是盖在窗口上面？**推荐常驻让位**，和 iPad 一样，窗口不被挡。
3. 默认开还是关？**推荐装好后默认关**，用磁贴打开，试用一周再定。
4. 一组最多几个窗口？**推荐 2 个**。
5. 竖屏怎么办？**推荐暂停**，转回横屏恢复。
